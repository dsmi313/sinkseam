# sinkseam

Empirical evaluation of whether the **slider (SL)** and **sweeper (ST)**
represent meaningfully distinct pitch classifications in MLB Statcast data
(2022–2024).

## Research question

Does the SL/ST pitch label predict outcomes (whiff rate, chase rate, wOBA
against) above and beyond the movement features themselves (pfx_x, pfx_z,
release_speed)?

## Historical context

The sweeper (`ST`) label was introduced by Statcast around 2022–2023.
Pitchers threw pitches with this movement profile for years before that —
they were just called sliders (`SL`).  This is the current version of the
sinker/two-seamer classification debate that MLB ultimately resolved by
collapsing `FT` into `SI`.  We ask whether the SL/ST split is real.

## Two-stage analysis

1. **GMM** (`mclust`) on pfx_x (sign-adjusted for handedness, glove-side
   positive), pfx_z, and release speed — does the data prefer two natural
   clusters, and do they align with the Statcast labels (ARI)?  An optional
   `INCLUDE_SPIN_AXIS` flag in `03_gmm.R` adds spin axis as a 4th feature.
2. **Bayesian hierarchical regression** (JAGS via `jagsUI`) with
   pitcher-level random intercepts.  The estimand is `beta_label`: a 95%
   credible interval that includes zero means the label adds nothing beyond
   movement.

## Running the pipeline

```r
# 1. Pull raw data (requires internet + baseballr).
source("R/01_data_pull.R")

# 2. Clean and engineer features/outcomes.
source("R/02_clean.R")

# 3. Fit GMM, compute ARI, save cluster assignments.
#    Set INCLUDE_SPIN_AXIS = TRUE in 03_gmm.R to add spin axis as a feature.
source("R/03_gmm.R")

# 4. Fit Bayesian hierarchical models (JAGS, ~20-60 min depending on hardware).
source("R/04_jags_model.R")

# 5. Render publication figures.
source("R/05_figures.R")

# 6. Compile manuscript.
rmarkdown::render("reports/analysis.Rmd")

# 7. Launch Shiny explorer.
shiny::runApp("app/")
```

## Key conventions

- `pfx_x` sign is **flipped for RHP** so glove-side break is always positive
  (opposite of the arm-side convention used for sinkers/two-seamers).
- Features are **standardised** (μ = 0, σ = 1) before GMM and JAGS.
- JAGS uses **precision parameterisation** (τ = 1/σ²) with flat Kéry & Schaub
  priors: Normal(0, 0.001⁻¹) for fixed effects, Gamma(0.001, 0.001) for
  precisions.
- Convergence criterion: Gelman–Rubin **R̂ < 1.1** for all monitored nodes.
- `jagsUI::jags()` is used (not `R2jags`), with `parallel = TRUE`.

## Outcomes

| Outcome | Type | Description |
|---|---|---|
| `whiff` | Binary | Swing-and-miss or foul-tip |
| `chase` | Binary | Swing at out-of-zone pitch (NA for in-zone) |
| `woba` | Continuous | Linear-weight wOBA (PA-ending pitches only) |

## Open questions (from concept paper)

1. **Spin axis** — include as a 4th GMM feature? Toggle `INCLUDE_SPIN_AXIS` in `03_gmm.R`.
2. **Year range** — restrict to 2023–2024 only to avoid early label-transition noise?
3. **Handedness matchup** — add same-/opposite-side covariate to outcome model?
4. **Prior sensitivity** — Kéry & Schaub flat priors appropriate on logit scale?
